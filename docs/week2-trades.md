# Week 2: synthetic trade contracts

This milestone provides a Python contract and pure parsers for in-memory synthetic executions.
There was no provider or trade specification in the repository, so the following small contract
is an explicit starting assumption. It describes one execution without inferring direction,
currency, venue, instrument taxonomy or trade correction semantics.

## Contract

`marketlab.trades.Trade` is a frozen Pydantic model. All five fields are required and additional
fields are rejected. Validation performs no whitespace trimming or identifier case conversion.

| Field | Contract |
| --- | --- |
| `trade_id` | Case-sensitive ASCII ID, 1–64 characters; starts with a letter/digit, then letters, digits, `.`, `_`, `:`, `-` |
| `symbol` | ASCII symbol, 1–20 characters; starts with uppercase `A`–`Z`, then uppercase letters, digits, `.`, `-` |
| `executed_at` | Aware `datetime` or `YYYY-MM-DDTHH:MM:SS[.ffffff]Z` / explicit `±HH:MM` offset string; normalized to UTC |
| `price` | Positive finite `Decimal` or plain decimal string; up to 12 integer digits and 8 fractional digits |
| `quantity` | Same numeric contract as `price`; fractional quantities are supported |

Timestamp text permits 1–6 fractional digits, requires seconds and a timezone, and rejects
invalid calendar dates, leap seconds and values that overflow when converted to UTC.
Numeric text has no sign, leading zeros (except `0.x`), whitespace, exponent or separators.
Floats, integers and booleans are rejected for decimal fields to avoid implicit conversions.
Python `Decimal` values follow the same positive, finite magnitude/precision bounds; their
existing exponent representation is permitted. JSON serialization emits decimals as strings.
These precision bounds are a canonical fixture contract, not claimed venue rules.

## Parsers

`parse_trades_json(payload: str)` accepts a JSON array of records. Decimal fields must be
JSON strings. Duplicate JSON object keys are rejected before a decoder can overwrite values.

`parse_trades_csv(payload: str)` accepts CSV text with exactly the five canonical headers,
each once, in any order. Quoted fields, LF and CRLF are supported. Header spelling is exact;
blank records, extra/missing columns and malformed quoting are rejected. No BOM removal,
provider column mapping or automatic field repair is performed.

Both parsers return a `tuple[Trade, ...]`, preserve input order and reject duplicate `trade_id`
values within the supplied batch. IDs are not deduplicated across batches. Parsing is
all-or-nothing: failures raise `TradeParseError`, with `record_index` set to a one-based data
record index when available. Schema failures retain the Pydantic `ValidationError` as their
cause. Syntax/header failures may have no record index; CSV data-record indexes are not physical
line numbers when quoted fields span lines. `[]` and a CSV containing only its valid header
are valid empty batches. Empty text is invalid.

## Deterministic synthetic fixtures

`synthetic_trades(count=8, seed=0)` returns immutable executions using a local seeded PRNG,
a fixed UTC start time, synthetic `SYN.*` symbols and integer-derived decimal values. It does
not access the clock, files, network, environment or global random state. `count` must be a
nonnegative integer, and `seed` an integer from 0 through `2**32 - 1`; booleans are rejected.
For the supported Python 3.13 runtime, the same seed/count produces equal results and a longer
batch preserves the shorter batch's prefix. IDs are unique within a batch and include the seed;
fixtures generated with the same seed intentionally reuse IDs.

`tests/fixtures/trades/valid.json` and `valid.csv` contain the three executions generated by
`synthetic_trades(3, seed=42)`. They are synthetic test source, not downloaded market data.
Tests compare both samples with the generator, validate malformed data and exercise decimal/timezone
round trips using the existing locked Hypothesis dependency.

No database migration, API route, ingestion, provider client or persistence is added. The existing
PostgreSQL and Ollama checks remain separate from these entirely offline trade tests.
