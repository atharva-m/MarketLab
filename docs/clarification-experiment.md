Two parts are (schema/outcome/intent) and (evidence/unresolved/reason). Three parts are (schema/outcome/intent), evidence, and (unresolved/reason). Each split call sees the full identical accumulated text/context turns and only its projected original output schema. Its system prompt contains the common domain bounds and its assigned instructions. Exact prompts and schemas are frozen in the plan and retained per request. Outputs merge by disjoint keys; no synthesis, retries, repairs or use of one call's answer as another call's input.

The fixed input set has nine cases: initial missing asset; complete BTCUSDT answer; remaining ambiguity; conflicting answer; and the first through fifth cumulative answers `I still have not chosen an asset.`. Every fixed case is sent even if an earlier case's response would be terminal. Consequently this assesses interpretation at fixed histories, not a durable end-to-end five-answer/sixth-answer workflow. There is no optional replacement run.

All requests use temperature=0, num_ctx=8192, num_predict=2048, stream=false, 120 s request deadline, disabled proxies/redirects/retries, and a 1 MiB response cap (including thinking). Equal output budget can truncate thinking responses; truncation is a failure, not repaired by enlarging the budget. Model digest is checked before and after every group. Full response JSON, including any thinking, is retained only in ignored local artifacts; public summaries report thinking presence/length and token counts without reproducing reasoning.

Scoring is predeclared separately: projected-schema validity; strict prompt/fixture compliance (all seven slots, preserved supplied context, absent symbols remain null, complete answer is BTCUSDT, evidence=context for context fields, missing/conflicting asset -> needs_clarification with symbols unresolved and an appropriate missing_fields/ambiguous/conflict reason; complete -> candidate/none/empty unresolved); retained interpretation()/decide() validator success and expected semantic outcome; combined strict and semantic success; cross-call consistency failures; truncation/timeout/errors; group wall time and native token/load timings. Safe validation rejection is reported separately from useful clarification. A complete answer's expected semantic result is candidate; every other fixed case expects needs_clarification and no executable candidate. These are exact field/outcome expectations, not a prose oracle.

The local server is separately owned by the parent on loopback 11442 with process-only OLLAMA_NUM_PARALLEL=3, MAX_LOADED_MODELS=1 and existing model files. No original service is restarted; no model pull, global setting or dependency change. HTTP overlap is measured from request intervals; actual inference parallelism requires server runner/slot evidence. Concurrent submission alone does not prove parallel model execution. All arms share the same server settings. Resource/cleanup/service preservation and actual outcomes are recorded by the parent. The script's prepare mode saves the immutable plan, script/fixture/runtime identities and exact request payloads before execution. Independent read-only review precedes actual calls.
